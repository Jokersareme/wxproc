# 发布与合规清单

## GPL-3.0 对应源码

本项目固定复用了 `tailuge/billiards`，并修改了物理渲染环境开关，增加无界面规则核心、联机协议、服务器、渲染和平台适配。根目录 `LICENSE` 保留完整 GPL-3.0，`UPSTREAM.md` 记录 commit，`THIRD_PARTY_NOTICES.md` 记录来源。

公开分发前必须：

1. 将完整对应源码发布到真实公开仓库，或运行 `corepack yarn source:archive` 并以符合 GPL 的方式提供归档。
2. 用真实地址设置 `SOURCE_URL` 后再构建，游戏“规则与开源许可”页会显示该地址。
3. 随小游戏保留 `apps/minigame/licenses/` 中的许可文本，并保留上游版权和修改说明。
4. 确认公开源码与发布客户端使用相同代码和资源，不能用旧版本或空仓库代替。

## 微信平台事项

- 使用游戏类目的正式 AppID，不是普通小程序 AppID。
- 在公众平台完成管理员、开发者、体验成员配置。
- 根据账号主体、商业化和当时审核规则准备实名认证、备案、软件著作权、版号或其他材料。本仓库不能保证免版号、免软著或审核通过。
- 首版不接支付、广告、排位、商城，避免引入无关合规范围。增加这些能力前重新评估资质。
- 隐私政策需说明登录标识、昵称、房间、对局回放和日志的处理方式；不要在客户端保存 AppSecret。
- 游戏名称、图标、截图和宣传语不得使用“腾讯桌球”或造成官方关联误解。

## 上传和提审

1. 跑通 `corepack yarn lint`、`corepack yarn test`、`corepack yarn test:e2e`、`corepack yarn build`。
2. 按 `docs/TESTING.md` 完成微信开发者工具和两台真机验收。
3. 在开发者工具上传代码，在公众平台把该版本设为体验版。
4. 两个体验微信号完成分享进入、整局对战、断线重连和再来一局。
5. 补齐后台隐私、类目和资质信息，提交审核。审核结果和所需材料以平台反馈为准。

本机没有你的 AppID、云环境权限和发布材料时，只能交付可构建、可部署的工程，不能声称已经上传或发布。
